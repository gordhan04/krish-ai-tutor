# KRISH AI TUTOR — P1.1 Learning-Flow Integrity Fix Report

## 1. Executive Summary

- **Phase Objective**: Fix runtime orchestration of the 6-phase learning cycle:
  `Objective → Explanation → Socratic Check → Practice → Explain-It-Back → Mastery`.
- **Root Causes Identified**:
  1. **Missing Tutor Engine Endpoints**: Practice start and answer submission were routed through generic assessment endpoints without full learning session state transitions and idempotency checks.
  2. **Illegal State Transitions**: State transitions from `REMEDIATION` to `CHECKING_UNDERSTANDING` were disallowed in the state machine matrix, causing UI exceptions during reflection attempts.
  3. **Frontend Phase De-synchronization**: Frontend was independently managing `currentPhase` state via local React state variables rather than strictly synchronizing with backend orchestrator responses (`syncLessonState`).
- **Results**:
  - All 69 backend tests passing (including newly added `tests/test_learning_flow_e2e.py`).
  - Frontend production build (`npm run build`) compiles cleanly without TypeScript or bundler errors.
  - End-to-end learning flow verified from lesson start through mastery confirmation.

---

## 2. Changes Made

### Backend
1. **`app/core/state_machine.py`**:
   - Ensured legal transitions between `REMEDIATION`, `CHECKING_UNDERSTANDING`, `PRACTICE`, and `EXPLAIN_IT_BACK`.
2. **`app/schemas/practice.py`**:
   - Defined request and response schemas (`PracticeStartRequest`, `PracticeStartResponse`, `PracticeAnswerRequest`, `PracticeAnswerResponse`, `ExplainItBackRequest`, `ExplainItBackResponse`) with optional `request_id` for idempotency.
3. **`app/services/tutor_engine.py`**:
   - Implemented `select_practice_question(session_id)` with concept resolution, cognitive calibration, and `QUESTION_SHOWN` structured event logging.
   - Implemented `record_practice_answer(...)` with idempotency guards, evidence-weighted mastery updates, and comeback bonuses.
   - Implemented `evaluate_explain_it_back(...)` with Feynman evaluation, idempotency guards, and progression to `MASTERY_REVIEW`.
4. **`app/api/v1/tutor.py`**:
   - Added routes `POST /tutor/practice/start`, `POST /tutor/practice/answer`, and `POST /tutor/explain-it-back`.
5. **`app/main.py`**:
   - Added global exception handler for `StateTransitionError` returning structured HTTP 400 with `{ "error": "INVALID_LEARNING_STATE", "detail": ... }`.

### Frontend
1. **`src/lib/api.ts`**:
   - Added client methods for `startPractice`, `answerPractice`, and `tutorExplainItBack`.
2. **`src/app/learn/[subjectId]/[chapterId]/[topicId]/page.tsx`**:
   - Added `syncLessonState(resp)` helper strictly synchronizing UI with backend `lesson_phase` and `state`.
   - Updated Socratic, Practice, Explain-It-Back, and Completion handlers to pass payloads to `syncLessonState`.
   - Added `errorNotice` banner for structured error reporting without crashing or freezing.
